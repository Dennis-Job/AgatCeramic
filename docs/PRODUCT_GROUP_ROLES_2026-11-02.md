# Роли характеристик группы товаров — 2026-11-02

## Заполнение карточек

На шаге «Варианты модели» каждой характеристике назначается одна роль:

| Роль | Сохранение | Покупатель |
| --- | --- | --- |
| Для выбора варианта | Значение принадлежит отдельному товару | Используется в переходах между вариантами |
| Индивидуальная | Значение и его очистка принадлежат отдельному товару | Показывается в характеристиках, если включена публичная видимость |
| Общая | Значение и его очистка синхронизируются всем участникам | Показывается по обычным правилам видимости |

Для плитки: цвет и размер плитки — для выбора; м²/штук в упаковке, вес и размеры
упаковки — индивидуальные. Общими оставляются только действительно одинаковые
свойства данной группы. Роли задаются группой, не глобальным справочником.
Обязательность и публичная видимость характеристик независимы от роли.
Для выбора требуется минимум одна скалярная характеристика; текст и множественный
выбор допустимы как индивидуальные или общие. Максимум 20 осей и 20 индивидуальных.

При создании похожего товара характеристики копируются как начальные значения.
Новая позиция остаётся самостоятельным товаром; заполните её упаковку и сохраните
группу с нужными ролями. В существующей группе сначала измените и сохраните роли,
затем редактируйте индивидуальные значения упаковки. Пока изменённые роли не
сохранены, сохранение значений блокируется. Подписи полей отражают сохранённую
группу самого товара, а не несохранённый выбор другой группы.

Старые группы автоматически не переклассифицируются: прежние оси остаются осями,
остальные свойства — общими. Если м² упаковки раньше входили в оси, вручную
переведите их в индивидуальную роль и сохраните группу. Превращение индивидуальной
характеристики в общую при разных значениях отклоняется без перезаписи данных.

Разные SKU могут иметь одинаковые цвет/размер. На сайте каждый остаётся отдельной
ссылкой на свою карточку. При одинаковых видимых осях подпись дополняется названием,
при совпадении названий — SKU. Параметры упаковки не добавляются в оси автоматически;
магазин не выбирает другую фасовку вместо покупателя.

## Excel

- В «Объединить товары» выгрузка содержит прежние «Ось 1»–«Ось 20» и новые
  «Индивидуальная 1»–«Индивидуальная 20». Остальные свойства категории общие.
- В выпадающих списках используются названия характеристик; технические ID скрыты.
  Текст и множественный выбор доступны в индивидуальном списке.
- Старые книги без новых колонок сохраняют индивидуальные настройки при изменении
  группы. Для новой группы отсутствие колонок означает пустой индивидуальный список.
  В новой книге пустые индивидуальные колонки означают явное очищение списка.
- Сначала импортируйте изменения ролей группы, затем значения товаров. Обычная
  товарная выгрузка и таблица редактирования категории содержат значения по SKU;
  их preflight и сохранение учитывают уже сохранённые роли.
- Импорт атомарен для групп, поддерживает возобновление и XLSX-отчёт об ошибках.
  Неподходящие роли/расхождения общих значений не приводят к частичной перезаписи.
- Дробные значения м² упаковки допустимы как характеристика. Количество заказа
  по-прежнему целое, 1–9999; пересчёт фасовок и складские предложения не добавлялись.

## Данные и выпуск

Добавлена только таблица `product_group_individual_attributes`; значения товаров
не мигрируют. Миграция прошла up/down/up на `agatceramic_feature_test` и применена
к локальному приложению. Очереди получили graceful restart, чтобы импорты использовали
новый код. API v15.0: optional `individual_attribute_ids` в запросах,
`individual_attributes` в Admin-ответах и `sku` в публичных участниках группы.
PATCH omission сохраняет текущий список; явный `[]` очищает его.
Rollback после редактирования индивидуальных значений требует согласованного
возврата приложения/данных: старый код снова синхронизирует неосевые поля.
