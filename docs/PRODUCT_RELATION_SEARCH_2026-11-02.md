# Связанные товары: добавление по SKU — 2026-11-02

Окончательный сценарий в `/products` → «Проверка» → «Сопутствующие и
рекомендуемые товары» использует одно поле SKU. Ранее применявшийся выбор
«Товар для добавления» удалён.

## Пользовательский сценарий

1. Ввести полный SKU; поиск запускается через 350 мс либо сразу по Enter.
2. Проверить название и SKU в карточке найденного товара.
3. Нажать «В сопутствующие» или «В рекомендуемые».
4. Поле очищается и снова получает фокус для следующего SKU.
5. Проверить добавленный список и нажать «Сохранить связи» один раз.

Пустое поле не загружает каталог и не выбирает товар по умолчанию. Начальная
загрузка случайных кандидатов также удалена. Совпадение принимается только по
полному SKU без учёта регистра и внешних пробелов; похожий SKU или название
не подставляется. Текущая карточка и уже добавленные товары исключены.
Сообщения поясняют запрет текущего SKU, повторное добавление, отсутствие
совпадения и ошибку запроса с действием «Повторить поиск».

Добавленный товар показывается обычным названием и SKU, без выпадающего
выбора другого товара. Тип связи и порядок остаются редактируемыми; строку
можно удалить. Удалённую связь можно подготовить к повторному добавлению до
сохранения: метаданные ранее выбранных товаров сохранены в локальном кеше.
Связи сохраняются одним существующим PUT; поиск и добавление сами не пишут БД.

## Реализация

- ProductRelationsSection использует существующие UiField/UiInput/UiButton,
  UiSelect для типа связи, UiAlert и UiEmptyState. Новые UI primitives и
  переопределения утверждённых цветов не вводились. Тип связи использует
  существующий плавающий режим меню, не обрезаемый родительским scroll-блоком.
- useProductEditor хранит точный результат SKU, отдельные состояния поиска,
  кеш подписей добавленных товаров и защиту от устаревших запросов.
  Начальная загрузка существующих связей защищена от позднего ответа после
  закрытия/повторного открытия той же карточки; до неё действия заблокированы.
- ProductRelationCandidateQuery ставит точный SKU первым перед сортировкой
  частичных совпадений по имени и применением limit. Регрессия использует
  25 более ранних по алфавиту совпадений при limit 1 и 20.
- API URL, параметры, schema и разрешения сохранены. Существующие backend
  ограничения self/outgoing/incoming связей действуют и для точного SKU.
  Поведение сортировки описано в API.md и OpenAPI. Миграции не требуются.
