# Фото товаров из таблицы Admin — 2026-10-03

В таблице `/products` пустая миниатюра заменена светлой кнопкой с плюсом.
Если фото задано, миниатюра показывает карандаш на затемнённой подложке при
наведении и клавиатурном фокусе. На touch-устройствах карандаш виден постоянно
в углу. Масштаб миниатюры сохранён: 48 × 48 px, фотография показывается целиком.
Визуальное поведение следует предоставленным скриншотам Ozon Seller и текущим
Seller tokens AgatCeramic.

Клик открывает фото-режим существующего `UiDialog`: заголовок «Добавление фото»
либо «Редактирование фото», название товара и `ProductImagesSection` без шагов
редактирования остальных данных. Загружается только коллекция фото товара.
Сохранены загрузка JPG/PNG/WebP до 10 МБ, удаление с подтверждением, изменение
порядка кнопками и drag-and-drop; первое фото становится обложкой. Загрузка,
удаление и порядок сохраняются сразу через существующие endpoints — об этом
сообщает footer. «Готово» закрывает окно. Не добавлялись новые типы медиа,
внешние импорты или инструменты обработки изображений из референса.

Миниатюра таблицы обновляется после загрузки, удаления и смены обложки. Есть
loading, ошибка коллекции с повторной загрузкой, сохранение выбранного файла
после upload error и защита от позднего ответа закрытого окна. Pending файл
очищается при закрытии/новом открытии. Во время сохранения закрытие блокируется.
Используются существующие focus trap, возврат фокуса, Escape и безопасный
backdrop close `UiDialog`; доступ определяется `catalog.manage`, backend
authorization сохранена. Фото в модальном окне использует `UiImagePreview`
с contain и fallback для недоступных URL.

## Исправление доступа к загруженным фото — 2026-10-03

Проверка реального тестового товара показала, что два PNG-файла успешно
сохранены в public disk, а записи API содержат правильные пути. Причина
ошибки отображения — отсутствовала ссылка Laravel `public/storage` на
`storage/app/public`: URL `/storage/product-images/...` возвращали **403**.
Описанное выше ограничение доступа к загруженным файлам устранено.

В работающем backend выполнен `php artisan storage:link`. В `compose.yaml`
создание этой ссылки добавлено между dependency bootstrap и запуском
Laravel server. Обновлены инструкции `docs/ENVIRONMENT.md` и task ledger.
Runtime-ссылка игнорируется Git; в репозиторий не добавлялись сами фото.
Файлы и записи товаров не изменялись, приватный диск не опубликован.

Проверки:

- До исправления URL существующего фото — HTTP 403; после исправления оба
  URL — **HTTP 200, Content-Type image/png**, размеры 345134 и 72605 байт.
- На реальном `localhost:5173/products` в окне тестового товара оба `img`
  успешно загружены: `complete=true`, natural size 1408×1858 и 764×672;
  обложка появилась в таблице. Результат визуально просмотрен.
- `docker compose config --quiet` — passed.
- Локальный backend пересоздан через `docker compose up -d --no-deps backend`;
  после запуска оба URL снова HTTP 200, ссылка и файлы доступны. PostgreSQL,
  Redis и frontend не пересоздавались.
- `git diff --check` — passed. UI-код, API-контракт и миграции в этом уточнении
  не менялись; unit/mocked E2E повторно не запускались, поскольку проверен
  реальный путь раздачи загруженных файлов, который такие тесты не покрывали.

Если окно уже показывало ошибку, его следует закрыть и открыть заново либо
обновить страницу, чтобы браузер повторил запрос изображений.

# Общие пустые состояния и открытие фото-модалки — 2026-10-03

Общий `UiEmptyState` показывает пустые коллекции Admin на голубой поверхности
Seller UI-kit с иконкой и читаемой подписью, без рамок. Фото товара без
изображений использует такое же состояние. Устаревшие фоны и рамки двух
потребителей (`ProductRelationsSection`, `ProductAttributesSection`) удалены,
поэтому shared-стиль не перекрывается локальными классами.

Действие внутри пустого окна использует отдельный `UiButton variant="soft-blue"`:
подложка кнопки голубая и немного темнее фона состояния.

Для фото-режима начальный фокус попадает на заголовок, который присутствует
сразу, даже пока загружается коллекция фото. Это устраняет tooltip на кнопке
закрытия при открытии; сама кнопка по-прежнему имеет доступное имя и показывает
подсказку при последующем ручном фокусе. Фокус заголовка использует Seller focus
token. Витрина UI-kit показывает оба варианта общего empty state.

Независимый UI Design Guard принял фото-модалку и пустое состояние без
блокеров. См. последующее уточнение от 2026-10-03 ниже; текущий вариант
пунктирную рамку не использует.
