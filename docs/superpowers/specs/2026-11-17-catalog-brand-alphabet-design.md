# Алфавитное меню брендов в каталоге

Дата: 2026-11-17. Статус: реализовано и проверено с уточнениями владельца от 2026-11-17.

## Задача

Добавить на `/catalog` под меню категорий алфавитную навигацию по выбранным
брендам. При наведении на букву открывается список брендов этой группы.
Составом управляет сотрудник в форме создания и редактирования бренда.
Скриншот первой версии AgatCeramic и https://www.antica.su/ задают принцип
работы; оформление использует текущий CLIENT_UI_KIT, а не старую палитру.

## Подход

Выбранное пользователем направление — отдельный переключатель у бренда.
Это прямое расширение существующего справочника: сейчас в нём уже есть
активность бренда, а каталог умеет фильтровать товары по его slug.

Автоматический отбор по категориям потребовал бы дополнительных правил для
смешанных брендов и лишил бы владельца прямого управления. Отдельный список
в CMS дублировал бы справочник. Эти варианты не предлагаются к реализации.

## Поведение

- В форме бренда добавить переключатель «Показывать в алфавитном меню каталога»
  и пояснение «Включите для брендов, которые нужно показывать под категориями».
  Он доступен при создании и редактировании с существующими правами управления
  каталогом. Поле независимо от «Активен».
- Дополнение владельца: быстрый переключатель «В алфавитном меню» доступен
  также прямо в строке бренда без открытия редактора. Сохраняет только этот
  флаг, не сбрасывает поиск/страницу, блокирует повторные действия на время
  запроса, сохраняет старое значение при ошибке и keyboard focus после ответа.
- Добавить `show_in_catalog_menu: boolean`, по умолчанию `false`, в БД,
  административные запросы и ответы. Существующие бренды автоматически
  не включать; их выбирает сотрудник. Отсутствие поля при частичном обновлении
  сохраняет прежнее значение.
- Публичное меню содержит только активные бренды с включённым переключателем.
  Состав не зависит от выбранной категории, фильтров, наличия и страницы выдачи.
  Выбранный активный бренд без товаров остаётся в меню и ведёт к обычной пустой
  выдаче каталога. Переключатель не меняет доступность товаров и обычного фильтра.
- Полоса: «Бренды», `0–9`, непустые буквы `A`–`Z`, `РУС`. Названия с первой
  цифрой собраны в `0–9`, кириллические — в `РУС`, латинские — по первой букве.
  Группировка использует название, а не транслитерированный slug. Начальные
  пробелы и кавычки пропускаются; латинские диакритические знаки нормализуются.
  Дополнительных групп не вводить. Бренды сортируются по названию внутри группы.
- Непустая группа открывается наведением мыши и нажатием; на сенсорном экране —
  касанием. Открыта одна группа. Переход курсора в выпадающий список не закрывает
  его. Пустые группы отсутствуют, включая `0–9` и `РУС`; когда выбранных
  брендов нет, полоса скрывается.
- Выпадающая панель занимает ширину контейнера каталога и содержит четыре
  колонки брендов на desktop. На узких экранах — две колонки, на самых узких —
  одна, чтобы длинные названия оставались читаемыми. Панель не обрезается
  липким контейнером категорий.
- Поддержать Tab, Enter/Space, Escape, закрытие по клику вне и уходу фокуса.
  Группы — кнопки с `aria-expanded`, бренды — обычные внутренние ссылки.
  Не переносить фокус автоматически при наведении или открытии нажатием.
- Предложение исполнителя: ссылка бренда ведёт на
  `/catalog?brand=<slug>#catalog-products`, начиная подбор с выбранного бренда
  без прежней категории, коллекции, страницы и ограничений выдачи. Новая страница
  бренда не нужна. Существующие canonical/noindex для фильтрованного каталога
  сохраняются.
- Предложение исполнителя: алфавитная полоса находится непосредственно после
  категорий и перед фильтрами/товарами, вне липкого контейнера категорий.
  При прокрутке закрепляются только категории, как сейчас. На узком экране
  полоса остаётся доступной над товарами, буквы переносятся без overflow,
  список ограничен шириной и доступной высотой экрана.
- Публичный `/catalog` и сохранённый `/preview/catalog` используют один компонент.
  На главную и другие CMS-страницы это меню не добавляется.

## Реализация

- Backend: безопасная обратимая миграция с default false, boolean cast,
  валидация Form Request, BrandResource. Сохранение проходит через существующий
  BrandManagementService и аудит изменений.
- Публичный каталог: добавить отдельное поле `brand_navigation` со списком
  `{ id, name, slug }` в ответ каталога, сохранив существующие поля. Query выбирает
  полный разрешённый список в БД независимо от пагинации товаров; API Resource
  формирует публичную проекцию. Обновить API.md и OpenAPI.
- Admin: существующие типы, сервис, начальное состояние формы и UI primitive
  переключателя; не создавать отдельный механизм сохранения.
- Client: отдельный feature-компонент алфавитной навигации, типизированный mapping
  ответа и SSR-ссылки. Текущие токены и общий паттерн анимации слоёв сохраняются.
  Новый паттерн описать в CLIENT_UI_KIT.

## Приёмка

1. Создание, редактирование, выключение, неактивный бренд, false по умолчанию,
   частичный PATCH, validation и существующие permissions проверены backend-тестами.
2. Меню содержит весь выбранный список независимо от категории и страницы товаров;
   выключенные и неактивные бренды отсутствуют в публичном ответе.
3. Проверены группы латиницы, цифр, кириллицы и прочих названий, пустые группы,
   переход к товарам, hover/click/touch, клавиатура, Escape и клик вне.
4. SSR содержит ссылки, нет hydration errors; пройдены релевантные backend,
   Admin и Client проверки, typecheck/build/format и проверка OpenAPI.
5. Визуальная проверка 320/640/768/1024/1280 px, длинных названий, reduced motion
   и независимое UI Design Guard review. Закрепление категорий не ломается.
6. Обновлены документация и статус задачи; проверен diff. Коммит — только
   по отдельному указанию пользователя.
