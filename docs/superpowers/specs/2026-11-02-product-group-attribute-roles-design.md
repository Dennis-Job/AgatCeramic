# Три роли характеристик группы товаров

Основание: владелец согласовал три роли и поручил реализовать создание/сохранение товаров, включая Excel.

## Поведение

- Для выбора варианта: `axis_attribute_ids`, заполненные скалярные характеристики, отображаемые в переходах между самостоятельными товарами.
- Индивидуальные: `individual_attribute_ids`, любые назначенные категории характеристики, включая текст и множественный выбор. Значения и очистка относятся только к конкретному товару; примеры — м²/штук в упаковке, вес, габариты.
- Общие: остальные характеристики категории, кроме зарезервированной legacy-коллекции. Совпадают при объединении и синхронизируются при сохранении значений.
- Роли задаются на уровне группы, списки осей и индивидуальных характеристик не пересекаются.
- Существующие группы сохраняют прежнее поведение: индивидуальный список первоначально пуст. Новая миграция только добавляет таблицу связей, не переписывает значения товаров.
- Несколько самостоятельных SKU могут иметь одинаковые значения осей: различная фасовка не должна заставлять включать упаковку в выбор. Каждый товар сохраняет свою идентичность, цену, остаток и URL; автоматический выбор SKU не добавляется.
- Если видимые оси совпадают, подписи дополнены названием; при совпадении и названия — SKU. Публичная группа передаёт SKU участника для этого случая.
- Новые поля в API: optional `individual_attribute_ids` в запросах; `individual_attributes` в admin response. Оmission при PATCH сохраняет текущий список, явный пустой массив очищает.
- В редакторе роли назначаются одним селектором на характеристику. Подписи и сохранение характеристик используют сохранённую группу самого товара, а не несохранённый выбор группы/ролей.
- Excel групп содержит явный индивидуальный список и пояснения всех трёх ролей. Старые книги без новых колонок сохраняют текущие индивидуальные настройки при обновлении; новые пустые колонки означают очистку. Обычный товарный Excel хранит значения отдельно по SKU и соблюдает те же правила синхронизации.
- Дробные значения характеристик упаковки допустимы; правило целого количества заказа 1–9999 не меняется.

## Подходы

Разрешить любые различия вне осей проще, но это убирает контроль общих свойств. Выбраны три роли: сохраняют контроль общих значений и отделяют выбор покупателя от индивидуальных параметров.

## Границы и проверка

Без новой складской модели, пересчёта единиц, автоматической комплектации и изменения утверждённой палитры. Регрессионные API/Excel-тесты проверяют локальные значения, общую синхронизацию, одинаковые оси и совместимость; Admin — create/clone/edit/save, клавиатуру и 320–1280 px. Независимый UI Design Guard обязателен. Исходные незакоммиченные изменения пользователя сохраняются, commit не выполняется.
