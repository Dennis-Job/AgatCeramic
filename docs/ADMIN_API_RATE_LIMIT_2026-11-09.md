# Ошибки 429 при смене статусов — 2026-11-09

## Причина и исправление

Все запросы API делили 60 запросов в минуту на IP. Успешная смена статуса
заказа или обращения запускает около девяти запросов: сохранение, карточку,
историю, комментарии, список, статистику, счётчики и уведомления. Открытие
следующей карточки и polling уведомлений дополнительно расходуют бюджет.
Несколько сотрудников за одним IP также блокировали друг друга.
Независимая проверка frontend не обнаружила автоматических повторов PATCH
или retry-цикла на 401/429; защита от повторного submit уже есть.

Авторизованные `/api/v1/admin/*` теперь используют 300 запросов в минуту
на ID сотрудника. Public/guest остаются на 60 запросах в минуту на IP;
ключи бюджетов разделены. Авторизованный магазин также остаётся в public
бюджете. Дополнительные ограничения login/reset/public forms сохранены.
Аутентификация Sanctum выполняется до throttle по приоритетам Laravel;
permissions и запрет доступа заблокированным сотрудникам сохраняются.

Обработчик HTTP-исключений сохраняет исходные заголовки, включая
`Retry-After` и `X-RateLimit-*`, вместе со стандартным JSON error-конвертом.

Отдельный 401 из сообщения владельца не содержит URL. Проверка
`/admin/auth/me` до входа штатно возвращает 401; причина конкретного ответа
без адреса запроса и состояния сессии не подтверждена.

- `backend/app/Providers/AppServiceProvider.php` — бюджеты admin/public.
- `backend/bootstrap/app.php` — сохранение заголовков HTTP-исключений.
- `backend/tests/Feature/Api/ApiRateLimitTest.php` — четыре regression tests.
- `docs/API.md`, `docs/openapi.json` — описание бюджетов и заголовков 429.
- Этот отчёт и `tasks/DONE.md` — результат и проверки.

## Проверки

Четыре regression tests сначала воспроизвели ошибки: 429 после 60 запросов,
общий бюджет admin/public и потерю Retry-After. После исправления 4 PASS,
512 assertions: реальные PATCH статусов и списки после прежнего порога,
граница 300, независимость сотрудников, сохранение бюджета при смене IP,
восстановление через минуту, изоляция public/admin и заголовки 429.

Pint (полный прогон 708 файлов и итоговый прогон трёх затронутых PHP-файлов),
PHPStan level 8, architecture guard, Composer validate/audit и OpenAPI lint
прошли. Architecture guard сообщает существующие рекомендации по сложности
незатронутых классов, блокирующих нарушений нет. Пять тестов OpenAPI tooling
прошли. Независимое code review: блокирующих замечаний нет.

Первый полный `composer test` остановился из-за memory_limit=128M в
`ProductImageImportTest::test_archive_safety_checks_still_reject_unsupported_entries`
(dataset `oversized metadata`). Полный повтор через
`php -d memory_limit=1G vendor/bin/phpunit --configuration=phpunit.xml --no-progress --display-skipped`
прошёл: 789 PASS, 7 SKIP, 8901 assertions. Пропущенные проверки требуют
PostgreSQL (Unicode-поиск брендов, точность checkout/payment и ограничения
коллекций); это не проверки лимитера.

Локальный HTTP smoke: публичный `/api/v1` — 200 с лимитом 60,
`/api/v1/admin/auth/me` без сессии — 401.

Изменений БД, SQL, миграций и frontend нет; отдельный PostgreSQL-прогон и
UI Design Guard для этого backend-only исправления не требуются. Данные
реальных заказов/обращений не изменялись, commit не создавался.
