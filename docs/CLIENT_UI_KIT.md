# Client UI-kit — AgatCeramic

Статус: утверждённое пользователем визуальное направление для клиентского
магазина. Применяется ко всем новым и изменяемым экранам `frontend/client/`
начиная с подготовки Phase 7. Архитектурные правила — в
[`frontend/client/AGENTS.md`](../frontend/client/AGENTS.md), порядок проверки —
в [`UI_DESIGN_REVIEW.md`](UI_DESIGN_REVIEW.md).

## Референс и границы

Визуальный референс — [`exampleSite.html`](../exampleSite.html), предоставленный
пользователем. Он задаёт спокойный премиальный editorial-стиль для магазина
керамики: тёплая нейтральная палитра, крупная фотография материала, свободное
пространство, тонкие разделители, сдержанная типографика и точные микроанимации.
Следовать узнаваемому визуальному языку референса на главной, в каталоге,
карточке товара, корзине, checkout и контентных страницах. Новый тип экрана
развивать из этих правил, а не вводить параллельную дизайн-систему.

PIETRA — демонстрационное имя в образце. Бренд проекта остаётся AgatCeramic;
логотип и реальные контакты, адреса, цены, товары, акции и юридические тексты
приходят из утверждённых источников проекта. Внешние demo-изображения,
подписка, отзывы, обещания услуг и имитация заказа не являются требованиями к
функциональности. Если ресурсов или данных нет, использовать честное состояние
пустоты/ошибки, согласованный asset или placeholder в той же композиции.

## Design tokens

При первой реализации перенести эти исходные значения в семантические CSS
custom properties под `frontend/client/app/assets/css/`. Дальше компоненты
используют tokens, а не собственные копии hex-значений. Изменять основные
значения только как осознанное изменение UI-kit с визуальной проверкой.

| Роль | Значение референса | Применение |
| --- | --- | --- |
| Основной фон | `#F2F1EE` | Страницы, hero, search |
| Второй фон | `#FAFAF8` | Чередующиеся секции, карточки, footer, drawer |
| Основной текст и тёмная CTA | `#141414` | Заголовки, основной текст, кнопки |
| Приглушённый текст | `#7A7772` | Подписи, метаданные, вторичный текст |
| Разделитель | `#E3E1DB` | Границы, тонкие линии, tabs |
| Тёплая подложка медиа | `#E9E6E0` | Фон изображений и пустых медиа |
| Белый | `#FFFFFF` | Инверсия, светлая CTA, поверхности |
| Плавная кривая | `cubic-bezier(.22, 1, .36, 1)` | Переходы и появления |

- Основной шрифт: **Inter**, начертания 400/500/600; загружать управляемым
  способом с предсказуемым fallback и без блокировки критического рендера.
- Заголовки: вес около 500, плотная строка, слегка отрицательный tracking.
  Hero `clamp(38px, 4.6vw, 64px)` и line-height около `1.06`; секционные
  заголовки `clamp(28px, 3vw, 40px)`. Body 13–15 px с комфортной строкой,
  особенно для русского текста.
- Eyebrow/label и компактные CTA: uppercase, 10–12 px, tracking около
  `.18–.22em`; применять к коротким подписям, не к абзацам или значениям форм.
- Контейнер: max-width `1280px`, горизонтальные поля `40px` на desktop и
  `20px` на узком экране. Базовый ритм секций около `110px` на desktop с
  адаптивным уменьшением. Сохранять свободное пространство.
- Формы геометричны: прямоугольные CTA, поля и фото без декоративных скруглений;
  круглые только явно предусмотренные icon controls. Тени минимальны; разделять
  секции преимущественно тонкой линией и фоном.

Контраст, размер клика и читаемость важнее буквального повторения мелких
чисел из демо. Если исходный muted-текст или 10px подпись оказываются
нечитабельны в реальном контексте, скорректировать соответствующий token и
зафиксировать решение; не исправлять это разрозненными локальными значениями.
В первой реализации `--color-muted` установлен в `#6E6B66`: исходный
`#7A7772` даёт контраст около 3.95:1 на основном фоне, а скорректированное
значение — около 4.7:1 для мелкого текста.

На первой главной поиск доступен в меню и явно обозначен как поиск по разделам
страницы. Глобальный поиск товаров появится вместе с публичным catalog API.

## Композиция и паттерны

| Паттерн | Обязательный характер |
| --- | --- |
| Header | Узкая service-полоска при наличии реальных данных; светлый sticky header с тонкой нижней линией, воздушной навигацией, лаконичными line icons и заметным состоянием active/focus. На малой ширине — доступное меню. |
| Hero | Крупная типографика и фото материала, desktop-композиция текст/изображение около 1:1, mobile — изображение над текстом. CTA ведёт на реальный маршрут. Автослайдер допустим только при наличии содержимого, controls и остановки анимации. |
| Секции | Центральный eyebrow, заголовок и короткое описание; чередование основного и второго фона, спокойные большие отступы. Не применять одинаковый состав секций ко всем типам страниц механически. |
| Категория | Крупное фото с близким к вертикальному aspect ratio, лаконичный заголовок и ссылка; вся карточка имеет понятную кликабельную область и keyboard focus. |
| Товар | Фото близко к квадрату, короткая метаинформация, цена с реальной единицей продажи, сдержанный статус/скидка. Кнопка корзины доступна без hover и отражает loading/error/disabled. |
| Фильтры и tabs | Текстовые controls с тонким индикатором active, достаточно крупной зоной нажатия; состояние выражено не одним цветом и доступно клавиатуре. |
| Промо | Тёмная полноширинная секция с контрастной светлой CTA. Показывать только подтверждённые предложения и условия. |
| Menu, search, cart | Светлые полноэкранный поиск или боковые панели поверх приглушённого backdrop; ясный заголовок, close, фокус и scroll management. Стиль панелей единый на всех маршрутах. |
| Footer | Воздушная многоколонная сетка на светлом фоне, реальные ссылки и реквизиты, тонкий нижний разделитель; на узком экране колонки складываются. |

Существующие паттерны развивать через `app/components/ui/`,
`app/components/shared/` и семантические tokens. Для состояния интерфейса
использовать типографику и плотность референса; ошибки и подтверждения должны
быть ясно читаемы и не полагаться только на цвет. Не вводить случайные яркие
акцентные цвета, массивные тени, pill-кнопки, декоративные градиенты,
нестандартный font или плотную dashboard-компоновку.

## Motion и responsive

Переходы мягкие и вторичны по отношению к содержимому: лёгкое появление
секций, деликатное масштабирование фото, движение стрелки CTA и панелей.
Не скрывать информацию или действие до hover/scroll. Учитывать
`prefers-reduced-motion`: отключать автопрокрутку, постоянный marquee и
необязательные переходы; контент должен быть виден и без JavaScript-анимации.
У слайдера должны быть подписанные controls, пауза при взаимодействии и
видимый текущий слайд. Не копировать таймеры из demo без lifecycle cleanup.

Контрольные ширины: 320, 640, 768, 1024 и 1280 px. Hero становится
одноколоночным, сетки карточек последовательно переходят с трёх колонок
на две и одну, footer и текстовые панели складываются. На телефоне кнопки,
поля и панели остаются управляемыми без бокового overflow; длинные русские
названия, цены и пустые изображения не ломают сетку.

## Правило принятия нового решения

Перед созданием экрана или общего компонента сравнить его с референсом и
существующими tokens/компонентами. При отсутствии подходящего паттерна
сначала предложить решение в том же визуальном языке и описать в этом файле
его роль, состояния, адаптивность и доступность. Существенное отклонение от
утверждённого направления требует согласования пользователя до внедрения.
Проверка результата и независимый UI Design Guard описаны в
[`UI_DESIGN_REVIEW.md`](UI_DESIGN_REVIEW.md).
