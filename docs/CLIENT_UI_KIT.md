# Client UI-kit — AgatCeramic

Статус: утверждённое пользователем визуальное направление для клиентского
магазина. Применяется ко всем новым и изменяемым экранам `frontend/client/`
начиная с подготовки Phase 7. Архитектурные правила — в
[`frontend/client/AGENTS.md`](../frontend/client/AGENTS.md), порядок проверки —
в [`UI_DESIGN_REVIEW.md`](UI_DESIGN_REVIEW.md).

## Референс и границы

Визуальный референс — [`exampleSite.html`](../exampleSite.html), предоставленный
пользователем. Он задаёт спокойный премиальный editorial-стиль для магазина
керамики: тёплая нейтральная палитра, крупная фотография материала, свободное
пространство, тонкие разделители, сдержанная типографика и точные микроанимации.
Следовать узнаваемому визуальному языку референса на главной, в каталоге,
карточке товара, корзине, checkout и контентных страницах. Новый тип экрана
развивать из этих правил, а не вводить параллельную дизайн-систему.

PIETRA — демонстрационное имя в образце. Бренд проекта остаётся AgatCeramic;
логотип и реальные контакты, адреса, цены, товары, акции и юридические тексты
приходят из утверждённых источников проекта. Внешние demo-изображения,
подписка, отзывы, обещания услуг и имитация заказа не являются требованиями к
функциональности. Если ресурсов или данных нет, использовать честное состояние
пустоты/ошибки, согласованный asset или placeholder в той же композиции.

UI-011 / 2026-10-21 — По указанию владельца подтверждение успеха повторяет toast
из `exampleSite.html`: ink-фон, белый текст 12 px с разрядкой .1em,
padding 15×28 px, без скругления/тени, по центру экрана снизу с отступом 32 px
(плюс safe area), z-index 200. Появление/уход снизу за .5 s с общей ease-out;
reduced motion отключает движение. Уведомление скрывается через 2600 ms;
новый успех заменяет текст и перезапускает таймер. На узком экране ширина
ограничена viewport минус 40 px, длинный текст переносится. Постоянный
`role=status`/`aria-atomic` объявляет текст без перемещения фокуса;
pointer-events:none сохраняет доступ к controls. Общий SSR-safe composable,
один host в app.vue (включая preview), очистка таймера при unmount.
Callback закрывает окно штатной leave-анимацией, затем показывает toast и
возвращает фокус инициатору. Partner очищает и сохраняет форму на месте,
без принудительной прокрутки. Ошибки остаются inline с `role=alert` и сохранением ввода.
Проверки: `success-notification.spec.ts`, `callback.spec.ts`,
`cooperation.spec.ts`, `overlay-motion.spec.ts`, `phone-mask.spec.ts`.

`UiDialog` остаётся native modal в top layer до завершения leave. Только затем
закрывает dialog, восстанавливает scroll/focus и сообщает `close` родителю.
Внутренние кнопки завершения используют slot `close`, как крестик/Escape/фон;
не размонтировать окно напрямую для обычного закрытия. При уходе со страницы
cleanup выполняется сразу. Уходящие меню/поиск становятся inert; scroll lock
и возврат фокуса снимаются после окончания анимации. Формы не получают autofocus.

### UI-007 / 2026-10-20 — Без сдвига страницы при scroll lock

На корневом `html` задан `scrollbar-gutter: stable` в `base.css`. Место под
классическую вертикальную полосу сохраняется при блокировке/возврате прокрутки,
поэтому ширина страницы и положение контента не меняются. Для overlay-scrollbars
лишний отступ не создаётся. Не дублировать компенсации через JS padding/margin
в меню, поиске или модальных окнах. Существующие scroll lock, анимации и
cleanup сохраняются.
Минимальная ширина body ограничена доступной шириной (`min(320px, 100%)`),
чтобы классическая полоса не создавала горизонтальный overflow на узком окне.
Проверка `scrollbar-stability.spec.ts` принудительно
включает настоящие классические scrollbars и сравнивает геометрию до/во время/
после каждого слоя. Обычный headless без полосы не доказывает отсутствие бага.

## Design tokens

### Независимые блоки баннеров / 2026-10-27

Уточнение владельца 2026-10-28: высота изображения «Меню баннеров» не зависит
от пропорций загруженного файла. Общий `HomeMaterialShowcase` резервирует рамку
4:5 с прежними ограничениями 520–620 px на desktop и минимумом 420 px до 900 px;
до 700 px сохраняет высоту `min(70vw, 420px)`. Изображение заполняет рамку через
`object-fit: cover` без искажения, с центральной обрезкой; отсутствие изображения
сохраняет размеры тёплой подложки. Публичная страница и saved preview используют
одну реализацию. Длинный текст может увеличивать текстовую часть без обрезки.
Проверка: переключение баннеров с разными пропорциями на пяти контрольных ширинах.

«Сетка баннеров» (`categories`, `HomeCategories`) и «Меню баннеров» (`materials`,
`HomeMaterialShowcase`) используют разные списки контента. Меню читает только
собственный `materials.items`, сохраняет клавиатурные вкладки и локальный выбор;
работает без сетки. Пустой/отключённый блок не подменяет данные соседнего блока.
Сетка отображает самостоятельные карточки, не переключает и не фокусирует меню.
По уточнению владельца от 2026-10-27 карточка с `link_url` становится семантической
ссылкой на собственный адрес: внутренние переходы используют NuxtLink, внешние —
безопасный HTTPS. Пустой/отсутствующий адрес оставляет обычную карточку.
Существующее увеличение изображения при наведении сохраняется и доступно при
focus-visible; сам hover не вызывает навигацию и не выбирает элемент меню.
У кликабельного баннера поверх изображения появляется прежняя плашка «Смотреть»:
отступы слева/снизу 24 px, padding 12×20 px, поверхность из
`--color-card-label-surface`, uppercase 10 px и прежнее плавное появление.
Плашка показывается при hover и focus-visible, скрыта от accessibility tree
как декоративная подпись ссылки; без ссылки она не обещает переход.
Reduced motion наследуется из общих стилей. Не удалять плашку при изменении URL
или разделении блоков.
По следующему уточнению владельца 2026-10-27 панель «Меню баннеров» также
переходит по собственному `materials.items.*.link_url`: одна ссылка охватывает
изображение и текст, а кнопки вкладок остаются снаружи и только выбирают баннер.
Плашка «Смотреть» в меню не добавляется. Примечание берётся только из выбранного
`materials.items.*.note`; пустое/отсутствующее значение скрывает примечание и не
подставляет legacy `materials.note`. Текущие стили текста/панели и общий focus
сохраняются; внутри ссылки нет вложенных интерактивных controls.
Утверждённые tokens, фото, сетка и компоновка меню сохраняются; технические якоря
`catalog` и `materials` остаются совместимыми с существующей навигацией. Названия

центральной колонки, с небольшим межстрочным интервалом и прежней разрядкой
по горизонтали. Для предельного объёма область ссылок ограничена
`min(144px, 25dvh)` с нативной вертикальной прокруткой, не скрытой через CSS: sticky header
не закрывает страницу, Tab прокручивает к следующей ссылке, отступы сохраняют
focus-visible. На ширине до 1024 px используется боковое меню со всеми пунктами
(до 16), поиском и возвратом фокуса. По уточнению владельца 2026-10-28 бургер
виден только до 1024 px включительно, на большей ширине отсутствует в Tab-порядке
и accessibility tree. При расширении окна открытое боковое меню закрывается,
scroll lock снимается после выхода, фокус возвращается видимому логотипу.
Это решение одинаково при SSR и hydration. Названия, ссылки и порядок задаются
в «Контент → Общее оформление → Шапка и навигация» и применяются после публикации.

автоматически не выделяются. Открытая панель получает фокус как контейнер без
обводки; переход к элементам по Tab сохраняет видимый focus и удержание внутри панели.
В меню, поиске, service-полоске и подвале длинные русские строки, включая строки
без пробелов, переносятся внутри доступной ширины. Цвета и типографика не меняются.

Верхняя service-полоска слева содержит управляемый текст общего оформления.
Справа по порядку — «заказать звонок», `site-settings.email`, единственный
телефон из `site-settings.phones`; email и телефон — кликабельные `mailto:`/`tel:` ссылки.
Композиция следует `exampleSite.html`: полоса от 40 px, текст 11 px с tracking
`.08em`, muted-цвет и тонкий разделитель. «заказать звонок» — со строчной
буквы, без подчёркивания. Между действием, email и телефоном — `·` с отступами
12 px по сторонам; разделитель переносится вместе со следующим контактом и
не появляется для отсутствующего контакта.
Публичное API сохраняет историческое имя текстового поля `header.topbar_right`,
хотя текст теперь расположен слева; сохранённый текст не переносится и не теряется.
Отсутствующие контакты не заменяются demo-данными; заказ звонка
доступен и при пустых настройках/ошибке их загрузки. На узком экране контакты
переносятся, а левый текст скрывается до 760 px, как в референсе. Публичный сайт и сохранённый
предпросмотр используют один `StorefrontHeader`.

Обратный звонок — отдельный feature: обязательный телефон, необязательное имя,
отправка через существующий `POST /callback-requests` и подтверждение успеха.
По уточнению владельца от 2026-10-21 email клиента не запрашивается, письмо
клиенту по заявке не отправляется. Получатель уведомления берётся из внутренней
«Почты для уведомлений» в настройках сайта (`notification_email`), не из `ADMIN_EMAIL`.
`UiDialog` — общий native modal с тёплым светлым фоном, тонкой границей,
затемнением, круглым close control и прямоугольной CTA. Ширина до 520 px,
отступы от края 20 px; на коротком экране прокручивается сам dialog.
`UiTextField` — подписанное прямоугольное поле без декоративного скругления,
высотой от 48 px, с видимым focus и состоянием disabled. Цвета берутся из
существующих tokens. При открытии фокус получает само окно без обводки;
поля и кнопки автоматически не выделяются. При переходе клавишей Tab видимый
фокус сохраняется: у полей темнеет граница, у кнопок остаётся обводка. Dialog удерживает фокус,
закрывается по Escape/фону и возвращает фокус инициатору. Во время отправки
поля, повторный submit и закрытие блокируются. Ошибки (включая 422/429) объявляются
через `role=alert`, loading/success — через `role=status`; ошибку можно исправить
без потери введённых данных. После успеха поля очищаются, окно закрывается,
а подтверждение показывает общий toast по UI-011. Контакты
клиента не попадают в URL, storage или application logs.

Страница `/cooperation` использует опубликованную CMS-страницу и отдельный
`partnership` feature. Контакт рядом с формой берётся из `partner_email`; общая
почта шапки и контактов остаётся `email`. Форма имени/телефона/email/предложения
использует общие `UiTextField`, `UiTextarea`, `UiButton`. `UiTextField type="email"`
использует native email validation. `UiTextarea` повторяет прямоугольную геометрию,
токены и focus полей по UI-002, имеет label, required/maxlength, disabled/readonly
и вертикальный resize; reduced motion наследуется из общих правил.
Partner submit создаёт обращение `partner`, не отправляет письмо-подтверждение.
Имя/email ограничены 255 символами, предложение — 2000; телефон канонический.
Все четыре поля обязательны. Ошибки 422/429/сети сохраняют ввод, ожидание блокирует
поля и submit, успех очищает форму и показывает общий toast по UI-011,
форма остаётся на месте; `retry: 0` исключает автоматические повторы.
SSR/preview, пять ширин, ошибки/успех/ожидание и сохранность ввода проверяются
в `cooperation.spec.ts`; персональные данные не записываются в URL/storage/logs.

`UiTextField type="tel"` автоматически применяет маску `+7 (XXX) XXX-XX-XX`.
Пустая модель отображается с `+7`; код страны не вводится и не удаляется.
Пользователь вводит десять цифр, может вставить полный российский номер,
редактировать середину, выделять и удалять цифры. Модель хранит канонический
номер без маски (`+74951204567`) либо пустую строку; неполный номер блокирует
отправку формы. Телефоны продавца, магазинов и клиентов показываются через
единый formatter как `+7 (495) 120-45-67`, а `href="tel:..."` использует
каноническое значение. Отдельные формы не создают собственных масок.

Контентные страницы используют крупный текстовый заголовок и упорядоченные блоки
в существующем ритме секций. Текст выводится обычным текстом с сохранением переносов,
без исполнения HTML. «Контакты» показывают публичные реквизиты и сетку магазинов с
семью днями расписания (две колонки, одна на телефоне). Каталог показывает реальные
категории и товары в сетке 3/2/1, квадратные изображения с честным fallback и цену с
единицей продажи; переходы в карточку и корзину добавляются в Phase 10. Пагинация —
подписанные ссылки с сохранением номера в URL. `PageState` — общий паттерн loading,
retryable error и empty: заголовок, пояснение, стандартная CTA с блокировкой повторного
запроса во время загрузки. Новые блоки не вводят дополнительных цветов или tokens.

Защищённый `/preview/<slug>` использует те же тела страниц и общие компоненты,
стили и motion, что публичный сайт. У успешного просмотра нет дополнительной панели,
изменяющей высоту hero; выбор размеров и уведомление о несохранённых правках находятся
в Admin. Загрузка, отказ доступа и ошибки используют `PageState` с клавиатурным retry.
Активный пункт шапки соответствует публичному пути страницы. В iframe основная
область и навигация имеют отдельные доступные названия, отличимые от Admin.
Режимы размеров, доступ и приватность описаны в [CONTENT_WORKSPACE_UX.md](CONTENT_WORKSPACE_UX.md).

## Motion и responsive

Переходы мягкие и вторичны по отношению к содержимому: лёгкое появление
секций, деликатное масштабирование фото, движение стрелки CTA и панелей.
Не скрывать информацию или действие до hover/scroll. Учитывать
`prefers-reduced-motion`: отключать автопрокрутку, постоянный marquee и
необязательные переходы; контент должен быть виден и без JavaScript-анимации.
У слайдера должны быть подписанные controls, пауза при взаимодействии и
видимый текущий слайд. Не копировать таймеры из demo без lifecycle cleanup.
На главном слайдере смена слайдов плавно перекрывается за `1s`: подпись
появляется с задержкой `0.15s`, слова заголовка поднимаются последовательно
с `0.3s` и шагом `0.1s`, описание — с `0.75s`, CTA — с `0.95s`.
При `prefers-reduced-motion` переходы и задержки отключаются.
Шкала без видимой подписи показывает ход `6.5s` до автоматической смены.
Ручной выбор слайда запускает отсчёт заново; при наведении, фокусе или
скрытой вкладке он останавливается вместе с автосменой. При одном слайде или
`prefers-reduced-motion` индикатор не показывается. На узком экране шкала
становится горизонтальной и располагается над кнопками слайдера; на самых
узких экранах точки выбора слайда стоят отдельной строкой.

Контрольные ширины: 320, 640, 768, 1024 и 1280 px. Hero становится
одноколоночным, сетки карточек последовательно переходят с трёх колонок
на две и одну, footer и текстовые панели складываются. На телефоне кнопки,
поля и панели остаются управляемыми без бокового overflow; длинные русские
названия, цены и пустые изображения не ломают сетку.

## Подменю навигации — согласовано 2026-10-28

Пункт с подменю — одна кнопка названия: нажатие только раскрывает список и не
открывает страницу. По уточнению владельца 2026-10-28 стрелка отсутствует только
в шапке сайта; в боковой панели сохраняется стрелка вниз с поворотом при
раскрытии. Обычные пункты остаются ссылками.
Один уровень вложенности; в Admin состав и порядок задаются вручную. Общий
`SiteNavigation` обслуживает desktop и боковую панель в существующих tokens.
На desktop — светлая прямоугольная поверхность с тонкой границей и мягкой тенью;
она использует native manual popover, чтобы не обрезаться прокруткой шапки.
Верхняя граница dropdown совпадает с нижней границей всего sticky header, без
наложения на него и без переворота вверх. Положение обновляется при scroll,
resize и изменении фактической высоты шапки через её общий ResizeObserver;
на коротком экране список прокручивается в оставшейся высоте. В боковой панели —
вложенный список без отдельной поверхности. Палитра и типографика сохраняются.

Открытие и закрытие обоих вариантов плавное за `--motion-disclosure-duration`
(0.35 s) с общей `--ease-out`. Desktop — opacity и смещение вниз на 6 px, включая
симметричный выход native popover через discrete display/overlay transition.
Боковой список разворачивается/сворачивается по фактической высоте через grid
0fr/1fr с opacity, без фиксированного max-height. Длительность и motion-классы
принадлежат `tokens.css` и `overlays.css`. Закрывающиеся/закрытые группы сразу
получают inert/aria-hidden и исключаются из взаимодействия, сохраняя визуальный
выход. Повторное открытие во время закрытия корректно разворачивает переход;
при смене групп прежний dropdown сохраняет своё положение до завершения выхода.
`prefers-reduced-motion` убирает смещение и почти мгновенно завершает переходы
по общему правилу base.css. Проверка — `navigation-submenu-motion.spec.ts`.

Одновременно раскрыта одна группа. Повторное нажатие, Escape, клик/фокус вне
навигации, переход по ссылке или открытие другой панели закрывают её. В drawer
Escape сначала закрывает группу с возвратом фокуса её кнопке, затем закрывает
панель. Кнопка имеет `aria-expanded`/`aria-controls`, дочерняя текущая страница —
`aria-current=page`; родитель получает визуальное active state без `aria-current`.
Видимый keyboard focus сохраняется. Скрытые списки исключены из Tab-порядка,
ссылки присутствуют в SSR DOM. Dropdown не блокирует прокрутку страницы.

Поиск находит вложенные ссылки по их названиям и по названию группы, исключает
повторяющиеся адреса. Родитель без адреса результатом поиска не становится.
Подвал сохраняет плоские ссылки: навигация проецируется в обычные и вложенные
адреса в исходном порядке с удалением дубликатов; самостоятельные ссылки
«Исследовать» не меняются. Preview использует те же компоненты и mapping.

Контроль: пять ширин, короткий viewport, предельные названия/число ссылок,
Tab/Shift+Tab/Enter/Space/Escape, normal/reduced motion, SSR/hydration,
взаимодействие с поиском и drawer. Проверки — `navigation-submenus.spec.ts`
и существующие регрессии `header-navigation.spec.ts`/preview/overlays.
Правило mobile-only burger и размещение ниже header дополнительно защищены
`header-menu-placement.spec.ts`, включая 1024/1025 px, sticky scroll,
промежуточный кадр анимации и короткий viewport с длинным меню.

## Правило принятия нового решения

Перед созданием экрана или общего компонента сравнить его с референсом и
существующими tokens/компонентами. При отсутствии подходящего паттерна
сначала предложить решение в том же визуальном языке и описать в этом файле
его роль, состояния, адаптивность и доступность. Существенное отклонение от
утверждённого направления требует согласования пользователя до внедрения.
Проверка результата и независимый UI Design Guard описаны в
[`UI_DESIGN_REVIEW.md`](UI_DESIGN_REVIEW.md).

Отображаемые цены и денежные суммы используют общую для приложения утилиту
`formatMoney`: `ru-RU`, неразрывный пробел между тысячами и перед `₽`, запятая
и две цифры копеек (`17 926,00 ₽`). API сохраняет decimal string без пробелов. Денежные поля редактирования также
должны показывать разделители тысяч; в Admin применяется `UiInput money`.
В текущем Client денежных inputs нет. Каталог при отсутствии цены сохраняет
«Цена по запросу».
