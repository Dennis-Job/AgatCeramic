# Команда и доступ — 2026-10-16

По выбору владельца объединены вариант 3 (карточки сотрудников) и вариант 2
(навигация по ролям слева, сведения и права справа). Используются существующие
Seller tokens, UiCard и CatalogReferenceLayout; палитра и шрифты сохранены.

## Поведение

- В меню «Управление» три ссылки заменены пунктом «Команда и доступ».
  Он открывает первый доступный сотруднику подраздел: сотрудники, роли или
  справочник прав. Активен на всех трёх адресах.
- Локальная навигация: «Сотрудники» и «Роли и права». Адреса `/employees`,
  `/roles`, `/permissions` и отдельные route guards сохранены.
- Сотрудники представлены карточками: инициалы, имя, статус, email, все
  назначенные роли, последний вход и действия. Сохранены поиск, фильтр статуса,
  создание, редактирование и подтверждение удаления. Фотографии, должности,
  приглашения и фиктивные глобальные счётчики не добавлялись.
- Роли выбираются в боковом списке с поиском по имени, коду и описанию.
  На экранах уже 1024 px используется select над содержимым. Выбранная роль
  сохраняется после перезагрузки данных; после создания или сохранения открывается
  сохранённая роль. После удаления показывается существующая роль.
- Назначенные права сгруппированы по модулям. Их просмотр не изменяет доступ.
  Редактор роли использует группы прав и поиск; поиск не сбрасывает выбор
  скрытых разрешений. Изменения применяются после сохранения.
- «Справочник прав» доступен из рабочей области ролей. Это список по модулям
  с поиском, фильтром и назначенными ролями. Справочник остаётся только для чтения.

## Доступ и API

Вкладки сохраняют независимые `admin-users.view`, `roles.view`,
`permissions.view`; действия требуют прежних manage permissions.
Нельзя получить доступ к закрытому подразделу через общий пункт меню.
Каталог системных прав не запрашивается при просмотре сотрудников или ролей.
Списки для форм используют прежние отдельные endpoints.

Имена ролей поступают из backend. Сотруднику назначается несколько ролей;
прямое назначение отдельных прав сотруднику не вводится.

Системная роль не удаляется, поля имени и кода в редакторе недоступны.
При проверке редактора исправлено прежнее несоответствие запросов действующему
API: обновление системной роли теперь отправляет только `description` и
`permission_ids`. Backend отвергает даже неизменённые `name`/`slug` в таком запросе.
Для пользовательской роли сохраняется полная форма.

Backend, OpenAPI и миграции не менялись. Рабочие данные не менялись:
браузерные сценарии выполнялись с изолированными API fixtures.
