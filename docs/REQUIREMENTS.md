# Требования AgatCeramic

## 1. Бизнес

AgatCeramic продает:
- керамическую плитку;
- мозаику;
- керамогранит;
- клей;
- затирки;
- сопутствующие материалы;
- сантехнику.

## 2. Клиент

Регистрация не требуется.

Минимальные данные заказа:
- ФИО;
- телефон;
- email, если нужен для отправки подтверждения;
- адрес доставки;
- комментарий;
- состав заказа.

Нужно предусмотреть валидацию и защиту от спама/ботов.

## 3. Заказы

Заказ должен иметь:
- уникальный номер;
- дату/время создания;
- контактные данные;
- адрес;
- состав;
- количество;
- цену на момент заказа;
- итоговую сумму;
- статус обработки;
- статус оплаты;
- дату оплаты, если оплата произошла вне сайта;
- дату передачи менеджеру;
- дату завершения;
- комментарии менеджеров;
- историю изменений.

ВАЖНО: дата создания заказа и дата оплаты — разные даты.

Аналитика должна учитывать продажи по фактической дате поступления оплаты, а не только по `created_at`.

Пример:
заказ создан 31 января, оплачен 2 февраля.
- январь: созданный заказ;
- февраль: реализованная/оплаченная продажа.

## 4. Статусы

Статусы заказа должны быть управляемыми, а не жестко зашитыми во frontend.

Базовый набор:
- новый;
- в обработке;
- ожидает уточнения;
- подтвержден;
- ожидает оплаты;
- оплачен;
- комплектация;
- передан в доставку;
- завершен;
- отменен.

Дополнительно нужен отдельный payment status:
- not_paid;
- pending;
- paid;
- refunded;
- partially_paid.

## 5. Каталог

Нужны:
- категории;
- вложенные подкатегории;
- перемещение категорий;
- SEO-поля категории;
- характеристики категории;
- группы характеристик;
- бренды;
- логотипы брендов;
- товары;
- варианты товаров;
- изображения;
- документы/файлы при необходимости;
- цены;
- остатки;
- единицы измерения;
- артикулы;
- SKU;
- штрихкоды;
- связанные товары;
- рекомендуемые товары.

Для плитки и керамогранита предусмотреть отраслевые атрибуты, например:
- коллекция;
- размер;
- толщина;
- поверхность;
- цвет;
- формат;
- материал;
- назначение;
- класс износостойкости;
- морозостойкость;
- страна производителя;
- количество в упаковке;
- площадь упаковки;
- вес упаковки.

Это не означает, что все характеристики должны быть жестко зашиты. Нужна динамическая система атрибутов.

## 6. Товарные варианты

Один товар/модель может иметь варианты.

Пример:
Плитка "Название":
- 600x600;
- 600x1200;
- разные цвета;
- разные варианты поверхности.

Нужно определить:
- какие поля относятся к product;
- какие к variant;
- какие характеристики задаются категорией.

## 7. Массовая работа

Администратор должен:
- импортировать товары из Excel;
- экспортировать товары;
- массово изменять товары;
- массово изменять цены;
- массово изменять остатки;
- массово менять категории;
- массово назначать характеристики;
- видеть ошибки импорта построчно;
- получать результат импорта;
- запускать большие операции через queue.

Нельзя выполнять тяжелый импорт синхронно в HTTP request.

## 8. Бренды

CRUD:
- название;
- slug;
- описание;
- логотип;
- SEO title;
- SEO description;
- активность.

## 9. Категории

CRUD:
- название;
- slug;
- родитель;
- описание;
- изображение;
- SEO;
- сортировка;
- активность.

Категории могут иметь неограниченную вложенность, если это не создаёт проблем с UX.

## 10. Характеристики

Нужно управлять:
- характеристиками;
- группами характеристик;
- типом значения;
- допустимыми значениями;
- единицей измерения;
- обязательностью;
- фильтрацией;
- отображением на странице товара;
- сортировкой.

Поддержать типы:
- string;
- text;
- integer;
- decimal;
- boolean;
- select;
- multiselect;
- date;
- range при необходимости.

Цветовые характеристики создаются с типом `select`: название цвета хранится в названии варианта,
а его код может быть HEX-значением (например, `#A1B2C3`). Отдельный тип `color` не используется.

## 11. Обращения

Нужен раздел обращений:
- обратный звонок;
- запрос ответа по email;
- обращение клиента;
- обращение партнера.

У обращения:
- тип;
- контакт;
- сообщение;
- дата;
- источник;
- статус;
- ответственный;
- комментарии;
- история обработки.

## 12. Контент сайта

Из админки управляются:
- телефон;
- основная email;
- реквизиты ИП;
- логотип;
- социальные сети;
- баннеры;
- главная карусель;
- информационные карусели;
- страницы;
- тексты;
- изображения;
- адреса магазинов;
- часы работы.

Нужен media management.

## 13. SEO

Управление:
- title;
- meta description;
- canonical;
- robots;
- OG title;
- OG description;
- OG image;
- slug;
- structured data;
- sitemap;
- redirects.

Для товаров, категорий и брендов SEO должно быть отдельным управляемым слоем.

## 14. SEO AI

AI должен помогать:
- создавать варианты title;
- создавать description;
- улучшать тексты;
- генерировать alt;
- выявлять дубли;
- предлагать ключевые запросы;
- проверять SEO-поля;
- создавать черновики.

AI-результат сначала должен попадать в draft/preview, а не автоматически публиковаться без предусмотренного workflow.

## 15. Аналитика

Dashboard должен показывать:
- заказы за день/неделю/месяц;
- продажи;
- оплаченные заказы;
- отмены;
- средний чек;
- количество заказов;
- динамику продаж;
- продажи по категориям;
- продажи по брендам;
- продажи по товарам;
- продажи по месяцам.

Отдельно учитывать:
- created_at;
- paid_at;
- completed_at.

## 16. Администраторы

CRUD:
- имя;
- email;
- статус;
- роль;
- permissions;
- последний вход.

Рекомендуемые роли:
- Super Admin;
- Administrator;
- Catalog Manager;
- Order Manager;
- Content Manager;
- SEO Manager;
- Analyst.

Права должны быть granular.

## 17. Безопасность

Нужно предусмотреть:
- authentication;
- authorization;
- rate limiting;
- CSRF/SPA security в выбранной auth-схеме;
- validation;
- audit log;
- безопасную загрузку файлов;
- ограничения MIME/размера;
- отсутствие исполнения загруженных файлов;
- секреты только через environment/secret storage;
- отсутствие PII в логах.

## 18. Что пока НЕ входит

Не включать без отдельной задачи:
- онлайн-оплату;
- клиентскую регистрацию;
- клиентский личный кабинет;
- программу лояльности;
- marketplace integrations;
- мобильные приложения.
