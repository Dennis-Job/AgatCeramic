# Единый размер и поведение полей Admin

Дата: 2026-10-03

## Результат

Проверены общие поля ввода, выпадающие списки, выбор даты и связанные контролы
админ-панели, включая формы товаров, фильтры, модальные окна и служебную
витрину UI-kit. В клиентском Nuxt-приложении проверен поиск в шапке: это
единственное общее текстовое поле; его крупная editorial-компоновка намеренная,
поэтому её не меняли.

Для стандартных Admin-полей сохраняется общий токен минимальной высоты
`--admin-control-height-md` — 36 px. Компоненты заполняют ширину своей колонки;
контейнеры должны сжиматься через `min-w-0`. Длинное содержимое теперь может
переноситься внутри контролов, не раздвигая соседние элементы и не выходя за
границы. Длинное значение однострочного поля обрезается внутри границы, если
перенос нарушил бы стандартную высоту.

В форме товара вручную собранное поле SKU было выше обычных контролов. Оно
приведено к 36 px, ширине колонки и типографике общих полей; длинный SKU
обрезается внутри поля, а полное значение доступно в DOM и `title`. Выбранное
значение `UiSelect` тоже остаётся однострочным; полный текст включён в доступное
описание. Подписи вариантов переносятся внутри списка, поисковое поле использует
общий токен высоты. Текст `UiRadio` защищён от выхода за границы.

Многострочный `UiTextarea`, выбор файла, checkbox/radio и сегментированные
варианты сохраняют размеры, подходящие их назначению. Они не являются
однострочными полями ввода.

Витрина и документация UI-kit теперь учитывают все 22 компонента `Ui*`, включая
общий `UiDialogFooter`; тест инвентаря синхронизирован с этим числом.

## Проверки

- `npm run lint` — passed.
- `npm run build` — passed; Vite сообщил существующее предупреждение о чанке
  размером более 500 kB.
- `npm run test:unit` — passed, 15 файлов и 90 тестов.
- Prettier `--check` для изменённых файлов — passed.
- `git diff --check` — passed.
- Полный Admin E2E: 267 passed, 27 failed из 294. Проверки адаптивности каталога
  и редактора товара на 320, 640, 768, 1024 и 1280 px прошли. Остальные падения
  относятся к screenshot baseline/проверкам исходных loading, empty и error
  состояний, а также к ожиданиям списка API-запросов в сценарии фото товара;
  эти тесты не проверяют изменённое поведение SKU, выбора или radio. Снимки не
  обновлялись.
- UI Design Guard принял изменения без блокирующих замечаний и статически
  проверил брейкпоинты 320, 640, 768, 1024 и 1280 px. Live visual run в браузере
  не выполнялся.
