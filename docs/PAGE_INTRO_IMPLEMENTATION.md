# Вступительные блоки страниц — 2026-11-10

После сравнения двух HTML-макетов реализован выбранный «Фон на всю ширину»:
изображение заполняет весь баннер, название и подпись поверх него в контейнере,
под текстом плавное осветление и переход к фону следующей секции.

## Использование

В Admin открыть «Контент → Страницы → [нужная страница] → Настройки →
Вступительный блок страницы». Можно загрузить фото или выбрать его из
медиатеки, добавить alt и вернуть стандартную иллюстрацию. Рекомендация:
2400×900 px, тёплая нейтральная гамма и место под текст слева. Фон использует
cover и кадрируется под экран; важные детали лучше располагать справа ближе
к центру. Стандартные фоны перегенерированы в 3:1 с сохранением сюжетов и
визуального направления первого референса.

Сначала сохранить черновик, проверить Nuxt-предпросмотр и опубликовать страницу.
Незагруженный выбранный файл блокирует сохранение/публикацию; переходы защищены
общим guard. Фото опубликованной версии не меняется при правках черновика.

Общий компонент работает на всех контентных страницах, если первый включённый
блок не является hero. Слайдер ниже содержимого не скрывает вступление и
использует H2, сохраняя один H1 у названия страницы. Это также относится к
сохранённому Nuxt preview. Страницы:
каталог, о нас, контакты, сотрудничество и новые страницы. Подготовлены также
иллюстрации услуг rezka/rospis; их доступность определяется публикацией страниц.
Добавлены опубликованные `/delivery`, `/payment`, `/designers` с безопасным
кратким текстом, обычными блоками CMS и отключённой до уточнения текстов индексацией.
Миграция `2026_11_10_000002_add_information_pages` создаёт только отсутствующие
страницы, сохраняет занятые draft/published slug и не удаляет контент при откате.
Подвал и навигация владельца не изменяются. У остальных новых slug используется нейтральная
композиция до выбора своего фото.

## Проверки

Исправление для «О нас»: нижний слайдер больше не скрывает вступление.
ContentPageBody определяет первый включённый блок; PageBlocks передаёт
контекст заголовка в HomeHero (H1 у ведущего слайдера, H2 у нижнего, включая
пустое состояние). Визуальный стиль слайдера сохранён через hero__title.
В Admin PageBlocksEditor и PageIntroEditor используют то же правило.
Проверены public SSR, saved preview, ведущий/нижний/пустой slider,
выключенные блоки, desktop/mobile. Client typecheck/build и 35 E2E PASS;
Admin build/lint и 3 E2E/axe PASS. Независимый UI Design Guard PASS.
Содержимое и порядок блоков CMS не изменялись.

Актуальная итерация панорамных фонов и новых страниц: девять изображений
2400×800 проверены по метаданным и визуально; Client typecheck/форматирование/
production Linux build PASS, 20 E2E (контент, preview, девять вступлений,
три новые страницы, 320–3840 px/axe) PASS. Backend: 36 CMS/preview/indexing/intro
тестов, 495 assertions PASS; отдельно InformationPagesTest 3/30 PASS,
Pint/PHPStan PASS. Миграция 000002 применена локально. Независимый UI Design
Guard принял новые изображения и реальные desktop/mobile страницы.

Файлы этой итерации: девять `*-wide.webp`, `app/utils/pageIntro.ts`, размеры
изображения у `PageIntro.vue`; `e2e/page-intro.spec.ts`, `info-pages.spec.ts`,
`mock-api.mjs`; backend миграция `2026_11_10_000002_add_information_pages.php`,
`InformationPagesTest.php` и обновлённые независимые тестовые slug в трёх
CMS-тестах. Новых API-полей и разрешений не добавлено.

Уточнение после выбора HTML «Фон на всю ширину»: Client typecheck,
форматирование и Linux production build PASS; 15 content/preview E2E и
итоговые 4 intro E2E PASS. Геометрия фона проверена на 320/640/768/1024/
1280/1920/2560/3840 px. Проверка ширины учитывает общий scrollbar gutter:
фон заполняет всю доступную ширину body, без горизонтального overflow.
Admin build, lint/format изменённого компонента, 2 intro E2E/axe PASS.
Независимый UI Design Guard подтвердил сравнение с HTML, mobile и ultrawide.
В этой итерации API и БД не менялись.

## Возможное развитие

Страницы «Доставка», «Оплата», «Дизайнерам» уже добавлены. Дальнейшее развитие —
страницы брендов/коллекций: короткое введение и тематический визуал перед содержимым.
Для категорий каталога полезны изображения соответствующих материалов.
Подключение к отдельным доменным страницам брендов/коллекций потребует их
собственного источника данных, а не создания контентных дублей.
