# План редизайна Admin по референсам Ozon Seller

Дата: 2026-10-01. Статус: TASK-A057–TASK-A062 завершены; финальная приёмка Linux/macOS пройдена.
Ограничение актуального Windows baseline зафиксировано в отчёте TASK-A062.

Основание — запрос владельца и пять приложенных скриншотов Ozon Seller. Цель:
верхняя глобальная навигация, подробные таблицы на всю ширину окна, просторные
рабочие области и визуальный язык предоставленных референсов.

Это изменение Admin Vue SPA. Этапы реализации — `TASK-A057`–`TASK-A062` в
[`tasks/TODO.md`](../tasks/TODO.md). Каждый этап заканчивается рабочим результатом
и собственной проверкой. Новый пользовательский запрос задаёт визуальное
направление вместо текущего TailAdmin-derived оформления; архитектура из
[`frontend/admin/AGENTS.md`](../frontend/admin/AGENTS.md) сохраняется.

## 3. Верхняя навигация

Две строки внутри белой шапки:

1. Логотип AgatCeramic, иконки уведомлений и меню сотрудника.
2. Главная, Товары, Заказы, Обращения, Контент, Управление, Настройки.

«Товары» объединяют список товаров, категории, бренды, группы характеристик и
характеристики. По уточнению владельца от 2026-10-02 массовые действия вынесены
в отдельные страницы меню «Товары»: «Добавить массово товары» (`/products/import`),
«Цены и статусы» (`/products/price-status`) и «Объединить товары»
(`/products/combine`). Экспорт Excel и добавление одного товара остаются в списке.
«Контент» объединяет страницы, общее оформление, магазины и отдельную медиатеку
с проверкой её собственного права. «Управление» объединяет сотрудников, роли,
права и журнал аудита. UI-kit размещается в служебной группе этого меню.
Профиль остаётся в меню сотрудника. Разделы аналитики добавляются по отдельным
бизнес-задачам, когда появятся их страницы.

Конфигурация ссылок единая для desktop и компактного меню. Ссылки фильтруются
по действующим permissions; пустые группы скрываются. Активный верхний раздел
определяется текущим маршрутом, включая внутренние страницы и query контента.
Хлебные крошки и заголовок поясняют положение внутри раздела.
Действующие route guards и backend authorization сохраняют контроль доступа.

По уточнению владельца от 2026-10-02 меню групп и окна иконок открываются
наведением мыши через общий `UiPopover`. Наведение не переводит фокус; небольшой
зазор до окна можно пройти без закрытия. Клавиатура поддерживает Enter/Space,
стрелки, Home/End, Tab и Escape с возвратом фокуса; на touch используется tap.
Открыто только одно окно шапки. Нижний разделитель находится внутри контейнера.

Desktop-подменю имеет по колонке на разрешённую непустую группу: ширина колонки
216 px, промежутки и padding 24 px, итог 264/504/744 px для 1/2/3 групп.
Окна иконок имеют максимум 320 px. Общий primitive ограничивает окно границами
viewport, при необходимости открывает вверх и даёт внутренний вертикальный scroll.
Высота закреплённой шапки учитывается таблицами и якорями. Dropdown не обрезается
table/card overflow.

При нехватке места разделы переходят в компактное меню в верхней шапке.
Постоянная боковая глобальная панель не возвращается. Локальные списки страниц
и блоков внутри редактора контента сохраняются как инструменты рабочей области.

## 4. Политика ширины

Уточнение владельца от 2026-10-02: меню, заголовки и нетабличные блоки всех
страниц должны иметь единый центрированный контейнер, как в референсе.
Только рабочие таблицы списков выходят за его максимальную ширину.

Общий `--admin-container-max-width` — 1280 px; gutters — 16 px до 640 px и
24 px далее. Внешний максимум шапки включает padding, поэтому её внутренние
края точно совпадают с контейнером страниц. Shared utility `.admin-container`
применяется к фильтрам, feedback, пагинации, форме медиатеки и мобильным
карточкам. `AdminWorkspace` сохраняет `min-width: 0` для grids и детей.

| Режим         | Применение                                               | Правило                                                                                           |
| ------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Обзор         | Dashboard, магазины, UI-kit                              | Единый центрированный контейнер 1280 px                                                           |
| Список        | Товары, каталог, доступ, аудит, медиа, заказы, обращения | Вводная часть и controls — 1280 px; таблица без максимальной ширины, локальный scroll             |
| Редактор      | Страницы, общее оформление                               | Рабочие зоны внутри 1280 px; container queries по фактической ширине                              |
| Простая форма | Профиль, настройки                                       | Page-level контейнер 1280 px; компактные внутренние редакторы/диалоги используют свои ограничения |

У заказов и обращений детали находятся под широким списком в общем
контейнере; явный выбор переводит фокус/прокрутку к деталям, предусмотрен
возврат к выбранной строке. Для контента три зоны доступны от 1240 px
внутренней ширины, поэтому список страниц, редактор и preview остаются рядом
на широком экране. Небольшие таблицы внутри обзоров и редакторов сохраняют
ширину своего блока; полноширинный режим относится к рабочим спискам.

Числа — стартовые значения, уточняемые визуальной сверкой с приложениями.
Перенос выполняется через semantic tokens и существующие `Ui*` компоненты.
Сначала сверить `/ui-kit`: кнопки, поля, badges, dropdown, dialog и состояния.
Для обзоров оставить карточки; для широких рабочих таблиц убрать лишнюю
внешнюю рамку и большие внутренние отступы. Светлый текст референса не должен
ухудшать действующий контраст и видимость фокуса.

Уточнение карточных поверхностей от 2026-10-03 (TASK-A063): самостоятельные
панели используют общие `admin-panel` styles и tokens с серо-голубой внешней
поверхностью; вложенные данные размещаются на белой поверхности. `UiCard`
использует этот стиль по умолчанию. Панели success/warning/error сохраняют
цвет своего состояния.

Уточнение секционных карточек от 2026-10-03 (TASK-A064): самостоятельный блок
с заголовком строится из серой внешней панели, серой шапки и отдельного белого
скруглённого тела. В Admin используется `UiCard` с именованным слотом `#header`;
в строках сетки белое тело растягивается на всю высоту карточки. Списки и таблицы
могут убирать padding тела через `:padded="false"`.

## Уточнение active/focus от 2026-10-02

По третьему референсу владельца активные поля и focus состояния становятся
мягче: один тонкий край 1 px и прозрачный halo 4 px через semantic tokens.
У переключателей/флажков спокойная выбранная обёртка, контрастный индикатор;
дополнительный focus появляется с клавиатуры. UI-kit централизует правила
в `styles/controls.css`, сохраняет error/disabled и forced-colors.
