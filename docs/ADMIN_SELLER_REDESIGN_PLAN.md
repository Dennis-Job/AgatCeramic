# План редизайна Admin по референсам Ozon Seller

Дата: 2026-10-01. Статус: TASK-A057 и TASK-A058 завершены; следующий этап — TASK-A059.

Основание — запрос владельца и пять приложенных скриншотов Ozon Seller. Цель:
верхняя глобальная навигация, подробные таблицы на всю ширину окна, просторные
рабочие области и визуальный язык предоставленных референсов.

Это изменение Admin Vue SPA. Этапы реализации — `TASK-A057`–`TASK-A062` в
[`tasks/TODO.md`](../tasks/TODO.md). Каждый этап заканчивается рабочим результатом
и собственной проверкой. Новый пользовательский запрос задаёт визуальное
направление вместо текущего TailAdmin-derived оформления; архитектура из
[`frontend/admin/AGENTS.md`](../frontend/admin/AGENTS.md) сохраняется.

- После TASK-A058 `src/layouts/AdminLayout.vue` использует двухстрочную верхнюю

- `src/layouts/components/AdminHeader.vue` содержит бренд, поиск, уведомления,
  меню сотрудника и навигацию. `src/styles/navigation.css` использует shell tokens.
- `src/styles/utilities.css` сохраняет `.admin-page { max-width: 1440px }`;
  политика ширины рабочих областей относится к TASK-A059–TASK-A061.
- `src/styles/tokens.css`, `typography.css`, `index.css` и `components/ui/` —
  общие точки переноса стиля без копирования CSS по features.
- Таблица товаров в `features/products/components/ProductEditor.vue` уже
  использует `UiTable`, фото, SKU, артикул, категорию, цену, остаток, статус и даты;
  сейчас её минимальная ширина — 1180 px, а таблица помещена в `UiCard`.
  Сам feature товаров уже не ограничен `.admin-page`; его ширину освобождают
  прежде всего замена sidebar и пересмотр общих отступов.
- `/content` уже не использует `.admin-page`. `PagesWorkspace` раскрывает две

  при 1600 px. После удаления глобального sidebar пороги надо перепроверить

- Поиск в текущей шапке — поле без подключённого сценария поиска. При переносе
  не обещать новый глобальный поиск; его бизнес-реализация требует отдельной задачи.

Все пути `src/` в этом документе относятся к `frontend/admin/`. Перед каждым
этапом повторно проверить затронутый feature и подходящие общие компоненты.

## 3. Верхняя навигация

Две строки внутри белой шапки:

1. Логотип AgatCeramic, существующий поиск, уведомления и меню сотрудника.
2. Главная, Товары, Заказы, Обращения, Контент, Управление, Настройки.

«Товары» объединяют список товаров, категории, бренды, группы характеристик и
характеристики. Импорт/экспорт остаются доступными через текущие действия списка.
«Контент» объединяет страницы, общее оформление, магазины и отдельную медиатеку
с проверкой её собственного права. «Управление» объединяет сотрудников, роли,
права и журнал аудита. UI-kit размещается в служебной группе этого меню.
Профиль остаётся в меню сотрудника. Разделы аналитики добавляются по отдельным
бизнес-задачам, когда появятся их страницы.

Конфигурация ссылок единая для desktop и компактного меню. Ссылки фильтруются
по действующим permissions; пустые группы скрываются. Активный верхний раздел
определяется текущим маршрутом, включая внутренние страницы и query контента.
Хлебные крошки и заголовок поясняют положение внутри раздела.
Действующие route guards и backend authorization сохраняют контроль доступа.

Меню групп открываются кликом и клавиатурой. Hover может быть дополнительным
способом открытия на устройствах с мышью. Обязательны Escape, закрытие вне меню,
возврат фокуса, доступные названия и `aria-expanded`. Высота закреплённой шапки
учитывается таблицами и якорями. Dropdown не обрезается table/card overflow.

При нехватке места разделы переходят в компактное меню в верхней шапке.
Постоянная боковая глобальная панель не возвращается. Локальные списки страниц
и блоков внутри редактора контента сохраняются как инструменты рабочей области.

## 4. Политика ширины

Режим выбирается явно общим page/workspace-компонентом, а не набором
неодинаковых `max-width` внутри страниц. На desktop наружный отступ рабочих
данных — ориентировочно 24 px, на узком экране — 12–16 px.
Сохранить `min-width: 0` для grids и их детей из действующего `.admin-page`.

| Режим         | Где применяется                                                                                         | Правило                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Обзор         | Dashboard, будущая обзорная аналитика                                                                   | Центрирование; ориентир максимума 1200–1280 px                                                                     |
| Список        | Товары, заказы, обращения, категории, бренды, характеристики, сотрудники, роли, права, аудит, медиатека | Таблица или список без максимальной ширины; заголовок и короткие фильтры могут быть центрированы, как на референсе |
| Редактор      | Страницы, общее оформление, подробное редактирование товаров; list/detail заказов и обращений           | Вся доступная ширина; пространство делится между необходимыми рабочими зонами                                      |
| Простая форма | Профиль, короткие настройки, компактные диалоги                                                         | Ограниченная ширина полей, обычно 720–960 px; нет растянутых одиночных полей на 2500 px                            |
| Смешанный     | Dashboard с небольшой таблицей; магазины внутри контента                                                | Ширина определяется назначением блока; наличие таблицы не делает весь dashboard полноэкранным                      |

Шапка может иметь центрированную внутреннюю часть около 1200–1280 px и на
полноэкранных страницах, как в Ozon. Рабочая таблица не наследует этот максимум.
Фильтры с большим количеством полей получают широкую панель; нельзя прятать
необходимые controls ради узкой вводной части.

## 5. Визуальная спецификация

| Элемент   | Целевой стиль                                                                                                                 |
| --------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Фон       | Белая страница и шапка; светлые серо-голубые подложки вспомогательных блоков                                                  |
| Акцент    | Яркий синий; стартовый primary `#005BFF`, остальные оттенки через tokens                                                      |
| Текст     | Тёмный основной текст; спокойный вторичный; контраст проверяется отдельно                                                     |
| Шрифт     | Сохраняем прежние локальные Nunito для основного текста и Poppins для display                                                 |
| Размеры   | Сохраняем существующие размеры текста, заголовков и межстрочные интервалы                                                     |
| Навигация | Компактные ссылки; тонкое синее подчёркивание активного раздела                                                               |
| Кнопки    | Синяя основная, светлая вторичная; высота около 36–40 px, радиус 6–8 px                                                       |
| Поля      | Светлая граница, умеренный радиус, ясный focus и ошибки                                                                       |
| Карточки  | Светлая подложка либо тонкая граница, радиус 16–20 px, минимум тени                                                           |
| Таблица   | Светлая шапка, тонкие горизонтальные разделители, белые строки, мягкий hover; без внешней округлой карточки у рабочих списков |
| Статусы   | Небольшие цветные badges с читаемой подписью; значение не передаётся только цветом                                            |
| Меню      | Белая поверхность, групповые заголовки, радиус около 12–16 px, мягкая тень                                                    |

Числа — стартовые значения, уточняемые визуальной сверкой с приложениями.
Перенос выполняется через semantic tokens и существующие `Ui*` компоненты.
Сначала сверить `/ui-kit`: кнопки, поля, badges, dropdown, dialog и состояния.
Для обзоров оставить карточки; для широких рабочих таблиц убрать лишнюю
внешнюю рамку и большие внутренние отступы. Светлый текст референса не должен
ухудшать действующий контраст и видимость фокуса.

## 6. Подробные таблицы и рабочие области

- Сначала перенести товары как образец для остальных списков. Показывать
  существующие полезные данные, не добавляя фиктивные поля или новые API.
- Названию дать больше места, разрешить перенос; перепроверить текущее сокращение
  названия при 50 символах, чтобы широкая таблица действительно показывала детали.
  Фото сохраняет пригодный для плитки и мозаики preview с fallback.
- Числовые колонки выравнивать вправо; идентификаторы, единицы измерения,
  статусы и даты показывать единообразно. Вторичные данные помещать под основными.
- Предусмотреть закреплённые заголовки; на горизонтальной прокрутке — идентификацию
  строки и доступные действия. Проверить совместимость с `UiTable` containment,
  локальным scroll, focus и текущими dropdown/dialog. Не закреплять слишком много
  колонок на узком экране.
- Для узких экранов использовать локальную прокрутку таблицы или существующее
  представление карточками; горизонтальная прокрутка всей страницы недопустима.
- Сохранить поиск, сортировку, фильтры, пагинацию, импорт, экспорт, CRUD,
  сохранение query и loading/empty/error/denied состояния, которые уже реализованы.
- В `/content` использовать освобождённую ширину для выбора страницы, блоков и
  настоящего Nuxt-preview. Защита несохранённых изменений, загрузки файлов,
  права доступа и раздельное сохранение/публикация остаются действующими.
