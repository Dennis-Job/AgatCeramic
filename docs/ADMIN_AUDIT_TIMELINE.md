# Журнал аудита — лента по дням

2026-10-16 владелец выбрал вариант «Лента по дням» из трёх показанных макетов.
Это второй этап после [обогащения событий](AUDIT_TRAIL_ENRICHMENT.md).

## Согласованная компоновка и план

- Вместо полноширинной таблицы — центрированная лента в существующем контейнере.
  Группировка по календарным дням Москвы, новые события выше; дата/время,
  сотрудник, понятное действие, объект/SKU и краткое содержание видны сразу.
- Изменения «было → стало» и остальные сведения раскрываются у события.
  Системные/старые/неизвестные события сохраняются без вымышленных данных.
- Сохранены поиск, точный фильтр action, даты, серверная пагинация, permissions
  и API. Список фильтруемых действий дополняется уже существующими action-кодами.
  Счётчики дня относятся только к загруженной странице.
- Сохранены Seller tokens, белая поверхность, синий акцент, Nunito/Poppins.
  Используются существующие UiButton/Badge/Input/Select/DatePicker/Pagination
  и feedback primitives. Общая дизайн-система и другие страницы не меняются.
- Сначала regression tests, затем feature-компоненты и отображение API-details;
  после — build/lint/format/unit, production E2E/axe и screenshot QA на
  320/640/768/1024/1280 и широких экранах, независимый UI Design Guard.

## Результат и проверки

Таблица заменена единой адаптивной лентой. Дни и время определяются в
`Europe/Moscow`, события сортируются от новых к старым; неизвестная дата вынесена
в отдельную группу. В записи показаны сотрудник/система, понятное действие,
раздел, объект/SKU, краткий итог. Счётчики явно подписаны «на странице».

Кнопка с `aria-expanded`/`aria-controls` раскрывает изменения «Было / Стало»,
остальные API-details и технический код действия. Фокус остаётся на кнопке;
Enter/Space раскрывают и сворачивают сведения. Email объекта находится внутри
подробностей. Вымышленные названия и изменения для старых записей не создаются.

Описание действия и значения берутся из существующего `details`. Стрелка
разделяется на before/after только для поля, подтверждённого `metadata.changes`
или существующими from/to status/assignee ключами. Неоднозначные строки с
несколькими стрелками сохраняются целиком; произвольные metadata не выводятся.
Без diff используется ограниченный preview значимых API-details: статус, роли,
главное фото, цена/остаток, итоги импорта. Не более трёх полей и 140 символов;
длинные значения полностью доступны в раскрытии. Технические файлы/IP/ID
в preview не попадают.

Поиск, даты, автоматическая фильтрация action и серверная пагинация сохранены.
Фильтр дополнен существующими action-кодами каталога, заказов, обращений,
контента, импорта и доступа. Fallback-словарь фильтра/полей синхронизирован с
`backend/app/Support/AuditLabels.php`; для новых кодов обновляются оба словаря.
Неизвестное действие имеет нейтральный заголовок и исходный код в подробностях.

Production E2E: 8/8 сценариев ленты, 2/2 существующих date-picker/container
регрессий, 12/12 audit baseline/responsive сценариев. Проверены
320/640/768/1024/1280/1440/2560, а container/baseline также 602/1920.
Длинные русские строки, keyboard/focus, pagination/filter reset, loading,
empty/error и axe проверены без новых нарушений и browser errors.

Независимый UI Design Guard принял результат после исправления preview для
событий без diff. Реальные screenshots просмотрены до обновления baseline.
Полный E2E всех маршрутов не запускался: shared UI/layout/tokens не менялись.
Linux Compose: production build и 8/8 сценариев ленты — PASS; после просмотра
снимков обновлены только audit baseline. Обычный повтор без update-snapshots:
12/12 baseline/responsive + 2/2 date-picker/container — PASS. Windows/Linux
default/loading/empty snapshots приняты; error snapshot остался без изменений.
macOS baseline в этой Windows-сессии не обновлялся; его нужно заново снять и
проверить на macOS при следующем прогоне этой платформы, не копируя PNG других ОС.

Build сохраняет существующее предупреждение о размере основного JS chunk
больше 500 kB; это не ошибка сборки и не расширяло область данной задачи.

Backend, миграции, OpenAPI и permissions не менялись. UI показывает сведения,
которые сохранены первым этапом; недостающие подробности старых событий
восстановить из отображения невозможно. Commit не создавался.
